ODOO MODULE · RECORDING STORAGE

Recordings off Twilio, into your bucket.

Connect S3 hands new recordings and voicemails straight to AWS S3 or any compatible endpoint, plays them back through short-lived presigned URLs, and offers a resumable wizard to move what's already on Twilio or in the Odoo filestore.

Why

Twilio bills for stored recordings. Odoo's filestore grows without natural compaction. Once a Connect deployment runs a year, two recordings per call adds up to a real ops problem: backups slow, replication costs climb, and deleting from Twilio without a verified copy is the kind of mistake nobody wants to be on call for.

How it works

  1. Pick S3 in settings
    Set Recording storage to S3 / Object Storage. Provide bucket, endpoint (blank for AWS, set for MinIO), region, and ERP-manager-protected keys.
  2. Verify the connection
    A test button runs head_bucket and tells you exactly which credential or permission is wrong instead of failing silently at upload time.
  3. New audio uploads on completion
    Recordings and voicemails upload as audio/mpeg on the same hook that previously stored them as Odoo attachments — same trigger, different destination.
  4. Playback uses presigned URLs
    Form widgets get 8-hour links; voicemail email notifications get 7-day links. Bucket can stay private.
  5. Migrate the backlog on your terms
    A wizard counts what remains on Twilio and the filestore, then processes one batch per click — idempotent, so re-clicking resumes after any interruption.

What's in the box

S3-compatible by default

Leave endpoint blank for AWS S3, fill it for MinIO, Wasabi, Backblaze, or any service that speaks the same API.

Verified delete

When Delete recording from Twilio is enabled, the bridge re-reads the S3 object first. If verify fails the Twilio copy stays.

Resumable batch migration

Wizard picks up only records still missing an s3_key. Tune the batch size, see last-run duration, click again until done.

Voicemail and call recordings both

One setting routes both connect.recording and the voicemail audio attached to connect.call through the same S3 path.

Tidy key layout

Objects land under connect/recordings/<db>/<sid>.mp3 and connect/voicemails/<db>/<sid>.mp3, so one bucket can host several databases.

Cleanup on delete

Unlinking a recording in Odoo removes the matching object from S3 too. Errors are logged, not raised, so a missing object doesn't block deletion.

Compatibility

Odoo 19.0 Python boto3

Depends on connect. Requires boto3. Works with any service that implements the S3 API.

Field note — the migration is the feature

Switching the storage backend is easy. Moving years of recordings without losing one is the hard part. The wizard runs synchronously, one batch at a time, with verify-before-delete — so if the connection wobbles you re-click and it resumes. Slower than a background job, easier to trust.
