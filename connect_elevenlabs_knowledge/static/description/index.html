Knowledge for your ElevenLabs agents.

Author URLs, files, and text snippets in Odoo. They land in your ElevenLabs knowledge base on save and attach to any voice agent that should know them. The agent's prompt config picks them up at sync — no copy-paste between consoles.

Why

Without this addon, agent knowledge lives in the ElevenLabs dashboard while the conversations live in Odoo — two places, two truths. This module makes the knowledge base a first-class Odoo model. Documents have status, retry, version timestamps, and an agent count. Edits push to ElevenLabs; renames push too; deletes push (with an explicit force-delete switch); and a sync button pulls anything created on the other side back into Odoo.

How it works

  1. Pick a document type
    URL, File (epub, pdf, docx, txt, html, md), or Text. The form swaps inputs based on the choice and validates file extensions before save.
  2. Save creates upstream
    On create, the record calls the right ElevenLabs endpoint — create_from_url, create_from_text, or create_from_file — and stores the returned knowledge_id with state active.
  3. Attach to agents via M2M
    A many-to-many on connect.elevenlabs_agent assigns documents. The agent's prompt config gains a knowledge_base array of active docs, sent on the next agent sync.
  4. Renames and unlinks propagate
    Writing name on an active doc patches it remotely; unlink deletes upstream first (honouring force_delete) and surfaces ElevenLabs's error message if the call fails.
  5. SYNC KNOWLEDGE pulls the other way
    A button on the ElevenLabs settings tab lists owned documents from the API and upserts them locally — anything created in the dashboard shows up in Odoo on next press.

What's in the box

Knowledge model

A new connect.elevenlabs_knowledge with name, type, content, description, size, created/updated, state, error message, and a force-delete switch.

Three input modes

URL, text snippet, or binary file. File names are constrained to .epub .pdf .docx .txt .html .md; invalid extensions raise on validate.

Agent ↔ document M2M

The agent_knowledge_rel table links docs to agents both directions. Add or remove triggers update_elevenlabs_agent on every affected agent.

Status workflow

Draft → creating → active → error, with a status bar, an error-message group that hides when empty, and a Retry Creation button when the API call has failed.

SYNC KNOWLEDGE button

One click on Connect Settings → ElevenLabs pulls up to 30 owned documents per page from the API and inserts or updates the local records.

Agents-using view

A View Agents action on the doc form opens the list of agents that have it attached, filtered by knowledge_base M2M membership.

Compatibility

Odoo 19.0 connect connect_elevenlabs ElevenLabs API

Depends on connect and connect_elevenlabs. Requires the elevenlabs Python SDK and a configured ElevenLabs API key in Connect Settings.

Field note — Odoo is the source of truth

Sync goes both ways but the bias is local-first: edits in Odoo push immediately, edits in the dashboard only land when someone presses SYNC KNOWLEDGE. If your team prefers ElevenLabs as the canonical place, this module will fight you. If you want the call, the agent, and its knowledge in one app, it gets out of the way.
