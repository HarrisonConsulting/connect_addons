ODOO MODULE · BRING YOUR OWN CARRIER

Keep Twilio. Add your carrier.

Connect BYOC creates a Twilio BYOC trunk and SIP credentials in your account, then routes selected outbound numbers through it using pattern-matched rules. The softphone, callflows, and recordings stay on Twilio — the call leg goes out your carrier.

Why

Twilio's signaling is excellent. Twilio's per-minute rate to certain destinations isn't. International routes, in-country compliance, or an existing carrier relationship can all justify keeping a SIP trunk you already own. BYOC stitches the two together — but configuring the Twilio side by hand (connection policies, trunks, credential lists, BYOC domains) is tedious. This module does it from the Odoo UI.

How it works

  1. Define a BYOC entry
    Friendly name and a SIP username/password create a Twilio BYOC trunk, a connection policy, a dedicated SIP domain, and a credential list — one click, four resources.
  2. List your origination URIs
    Add sip: or sips: targets with priority and weight. Each one syncs to Twilio as a connection-policy target.
  3. Write outgoing rules
    A rule matches a number prefix and points to a BYOC trunk. The deepest-matching rule wins; optional prefix add or leading-digit trim adjusts the dialed string.
  4. Caller-ID resolves by case
    User caller ID, BYOC default, and country match interact through five explicit cases — so cross-border calls present a number your carrier will accept.
  5. Sync pulls Twilio state back
    A sync action reconciles BYOC trunks in Twilio with Odoo records, surfacing trunks added or removed externally as on-screen notifications.

What's in the box

Twilio resources from one form

Trunk creation provisions the connection policy, BYOC domain, and SIP credential list together — including unique subdomain and webhook URLs.

Prioritized origination targets

Multiple SIP URIs per trunk with priority and weight, kept in lock-step with Twilio on create, write, and unlink.

Prefix-match outgoing rules

Pattern-based routing with optional leading-digit trim and prefix add, ordered by deepest match so specific rules beat generic ones.

BYOC caller-ID type

The caller-ID model gains a BYOC type linked to a trunk, and onchange handlers keep the type and BYOC reference consistent.

Country-aware fallback

When the user's caller ID and the destination disagree on country code, the dialer falls back to the BYOC's default — instead of getting rejected at the carrier.

SIP password rules from Twilio

Password changes route through Twilio's credential list API, surfacing the platform's strength rules as native Odoo validation errors.

Compatibility

Odoo 19.0 Twilio BYOC

Depends on connect. Requires a Twilio account with BYOC enabled and your carrier reachable over SIP.

Field note — opinionated about caller ID

Most BYOC failures we see in the field are caller-ID problems: the user's preferred number doesn't pass at the carrier, or international routes spoof the wrong country. The five caller-ID cases are deliberate, not over-engineered. If your carrier accepts anything, you'll never notice — that's the point.
