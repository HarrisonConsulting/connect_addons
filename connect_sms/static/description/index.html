One Twilio account, every Odoo SMS.

Why

Connect manages Twilio numbers, credentials, and webhook security for telephony. But Odoo's built-in SMS marketing, chatter SMS, and automation rules use a separate provider abstraction (sms_twilio) with its own credentials and number list. Without a bridge, you maintain two configurations of the same Twilio account — and history splits across two models.

How it works

  1. Installs auto on dependency match
    When connect and sms_twilio are both installed, the bridge installs itself and runs a one-shot sync.
  2. Credentials flow one direction
    Account SID and auth token written in Connect settings copy into every company's sms_twilio configuration on save.
  3. DID numbers sync to senders
    Outgoing caller IDs of type number populate sms.twilio.number; plain caller IDs are skipped because they cannot send SMS.
  4. Sent messages journal back
    After Odoo's pipeline returns a Twilio SID, the bridge writes a matching connect.message so Connect's message history stays the canonical view.
  5. Delivery updates round-trip
    Status callbacks landing on sms.tracker propagate to the connect.message record by Twilio SID.

What's in the box

Credential sync on write

Connect settings respect the protected-field write pattern, so the second write — the one carrying the real token — triggers the sync.

Number list reconciliation

Adds new DID numbers and removes stale ones per company on every caller-ID sync, keeping sms.twilio.number in step with Connect.

Unified message journal

SMS sent through marketing, chatter, or automation lands in the same connect.message log as SMS sent from the softphone.

Compatibility

Odoo 19.0

Depends on connect and sms_twilio. Marked auto_install — installs once both are present.

Field note — a bridge, not a replacement

This module does not move SMS sending out of Odoo's pipeline. It threads Twilio's credentials and numbers through the standard provider abstraction so the rest of Odoo behaves normally. If you want Connect to own the send path, this is the wrong module — keep using its softphone composer.
